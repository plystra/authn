# Resources

The installed CLI `0.1.0` discovers consumer Resource contracts in current and dependency Projects. Use `plystra inspect resources --format json` to inspect exact IDs, packages, owning sources, and contract_digest values without mutation. Declare one non-generic defined Go interface Resource with exactly one //plystra:resource <resource-id> directive. Do not attach Interface directives or interface.yaml projection metadata, and keep lifecycle control on providers. Duplicate IDs and malformed declarations or bounded public type shapes fail with source-bearing PLYSTRA_RESOURCE_ID_DUPLICATE, PLYSTRA_RESOURCE_DECLARATION_INVALID, or PLYSTRA_RESOURCE_CONTRACT_INVALID diagnostics.

Contract digests retain transitive public fields and methods, normalized aliases, instantiated generic arguments, and recursive references, with limits of 64 type-reference levels and 65,536 public shape nodes. They exclude comments, source locations, private implementation details, and unrelated provider lifecycle hooks. Installed support reports resource.contract separately from named-instance configuration and execution.

Resource provider discovery validates exactly one //plystra:implements-resource <resource-id> directive on an exported non-generic package-level constructor. Use an optional first same-package Config value, then explicitly named canonical Resource parameters, and a concrete pointer plus error result assignable to the exact visible Resource. Do not mix ordinary Interface directives on that constructor. Invalid declarations and typed signatures report PLYSTRA_RESOURCE_PROVIDER_DECLARATION_INVALID or PLYSTRA_RESOURCE_PROVIDER_INVALID with owning sources. Installed resource.provider.discovery reports validation separately. Discovery alone does not select or execute providers; resources.instances supplies the named selection.

Ordinary Implementation constructors may also declare explicitly named canonical Resource parameters alongside required and optional Interface dependencies. Use plystra inspect implementations --format json to inspect resource-contract nodes with resource_id and contract_digest, and declares-dependency edges with reason resource, exact parameter_name and one-based parameter_position. Repeated parameters for the same Resource remain distinct. These declarations are not Interface requirements or runtime activation. Selected instances and resolved bindings appear separately in inspect resources. Installed resource.consumer.discovery covers discovery and inspection of dormant explicit and unselected candidates. Malformed Resource-shaped parameters fail with source-bearing PLYSTRA_IMPLEMENTATION_REQUIRED_RESOURCE_INVALID. Reachable consumers require named Resource bindings; dormant choices remain inactive.

Named instances are authored under resources.instances.<name> with one exact use provider constructor and typed instance-owned config, not top-level config. Names are exact, 1 through 128 ASCII bytes, matching [a-z][a-z0-9]*(?:-[a-z0-9]+)*(?:\.[a-z][a-z0-9]*(?:-[a-z0-9]+)*)*. A config-only environment overlay may keep the lower provider. With the same provider, non-pointer fixed Config structs compose by field and pointers and collections replace atomically. Changing use replaces the whole instance and discards old configuration even when field names match. Requiredness and defaults apply after composition. Dependency Projects remain inactive configuration sources.

Bind exact Go parameters with resources.bind.implementations.<constructor>.<parameter> or resources.bind.instances.<consumer-instance>.<parameter>. Each leaf names one exact instance; the old flat binding form is invalid. Explicit targets must exist and conform to the required Resource. Otherwise exactly one compatible selected instance binds implicitly; zero is missing and multiple matches are ambiguous. Provider identity and declaration order never break ties. All explicit addresses are validated, including dormant Implementation consumers. Remove an instance or binding leaf only with {$remove: true}; null and empty mappings are not removal. Removal never silently retargets an explicit binding; dangling addresses and dependency cycles fail before generation.

Malformed Resource configuration reports PLYSTRA_RESOURCE_METADATA_INVALID, PLYSTRA_RESOURCE_CONFIGURATION_SCHEMA_INVALID, or PLYSTRA_RESOURCE_CONFIGURATION_VALUES_INVALID without private values. Invalid instance selections report PLYSTRA_RESOURCE_INSTANCE_INVALID. Missing, ambiguous, or invalid dependency targets report PLYSTRA_RESOURCE_BINDING_MISSING, PLYSTRA_RESOURCE_BINDING_AMBIGUOUS, or PLYSTRA_RESOURCE_BINDING_INVALID with owning sources. Correct the selected instance, exact consumer/parameter address, or required typed field, then rerun the same selector; do not remove a still-needed dependency to bypass validation.

Every selected instance is active even when unconsumed. The same provider under different names produces distinct values, Config owners, and lifecycle members. Each named instance is constructed once and shared across its consumers. Providers depend only on Resources; Implementations may mix Resource and Interface dependencies. Resources do not create Interface roots, catalog entries, governed proxies, exposure, or transport output. Dependencies construct and start first; consumers stop first. Constructors only assemble values, with acquisition in Start. Failure cleanup includes non-nil partial constructor results and never-started lifecycle values; Stop must tolerate those states. Nil/nil and panics fail safely, and bounded cleanup failures remain retryable.

Generated typed configuration and Secrets are loaded per instance from the selected documents and source-independent private runtime baseline. Validate every selected object before resolving Secrets or entering constructors. Runtime compatibility version 12 and frozen model version 19 cover named Resource structure. Instance identity, providers, bindings, and build-visible edits require regeneration and rebuilding. Valid runtime-only values and Secret references do not enter public generated identity; public artifacts exclude private values, reference targets, and private hashes.

Use plystra use <target> <constructor-symbol> for a canonical Interface ID including /vN or an existing named Resource instance, with no kind flag. It never creates an instance. An exact provider change discards only that instance's old Config; the same provider and other instances retain their configuration. Selection removes configuration whose last explicit or reachable owner disappears and only provably obsolete consumer binding parameters. Cleanup writes selected-layer tombstones or sparse deltas and never edits a dependency or copies a baseline. Still-owned configuration remains intact. Surviving dependencies and new required values must be valid; the CLI never guesses a binding or retargets unrelated consumers. The command regenerates and validates the repaired final state in its rollback boundary, even when the starting graph is invalid.

`plystra implement <contract> --package ./<package>` creates an unfinished, inactive ordinary Resource provider scaffold. It does not create a named instance, select a provider, infer configuration, or provide runtime behavior. Author `New`, provider methods, configuration, dependencies, and lifecycle hooks before runtime use; no guessed Config, dependency, or hook is added. The command regenerates and builds the complete selected application in the scaffold rollback boundary, without running application tests or business methods. Instance creation remains unsupported. After manual Go or YAML edits, run `plystra generate`, `plystra generate --check`, and `plystra check` with the same selector. Never hand-edit generated assembly. Installed `resource.provider.scaffold` reports scaffold stages separately from `resource.provider.selection` and full Resource acceptance; implemented stages do not establish `accepted=yes`. `plystra change plan --request change.json --format json` supports batches of `interface_root` present/absent (require or expose), `implementation_selection` set/remove, `resource_selection` set/remove, and `configuration` set/remove operations (at most 1,024 requested operations) and emits a read-only `plystra.change-plan/v1` payload. Source and dependency previews also accept interface_create, implementation_create, and dependency add/remove/update operations, jointly resolve module targets and materialize all sources before discovery, and validate the complete selected candidate with go build -mod=readonly ./... in a private working copy. Same-request contract imports, selections, roots, and typed configuration edits are supported. Implementation scaffolds remain unfinished; application tests and business methods are not run. Original inputs are rechecked and temporary trees are removed before success. Planned writes include authored and generated creations, replacements, deletions, and the private baseline without private digests. `change apply`, primitive-command lowering, and `--dry-run` remain uninstalled.

Resource removal previews remove the whole exact named instance, including provider and Config. Complete documents delete it; environment overlays retain a whole-instance exclusion. Only the removed consumer's outgoing binding leaves are cleaned up. Surviving explicit bindings are never erased or retargeted; implicit dependencies resolve against the final instance set. Missing or ambiguous dependencies and unrelated invalid Config fail without a partial plan. Invalid obsolete selected-layer Config may be removed, but typed lower-layer validation is unchanged.

Configuration previews name an exact owned Implementation constructor or effective Resource instance and an owner-relative declared field path. Paths traverse only non-pointer fixed objects; supply atomic values whole. Removal deletes the exact field in a complete document or records an exact environment exclusion, including when root lacks a value. Invalid scalar ancestors and ancestor exclusions cannot be overwritten to widen the edit. All final Config and bindings must validate, even for no-op removals. Public request identity omits values; every configuration set declares a planned write, even for equal values or identical bytes, to hide private equality. These previews remain non_exact and cannot authorize apply. Configuration-only batches accept up to 1,024 disjoint operations and validate only the complete final state. Same-owner ancestor/descendant targets conflict regardless of order. Interface roots, Implementation selections, and Resource selections may be batched together, with or without disjoint configuration edits. All selections share the final ownership graph and one selected-document edit. The complete request permits at most 1,024 requested operations. Fields use final owners and their exact schemas; choice changes, obsolete Config and binding cleanup, and field edits share one document edit. Every multi-operation selection batch requires a valid complete final state and does not enumerate missing-value decisions. Public plans allow at most 1,024 derived operations separately from requested operations. Dependency removal/update preconditions use the captured original go.mod. Resolved target versions survive generation and tidy; conflicts fail. Captured old and final declarations prove owner and obsolete parameter cleanup and newly required fields on unchanged constructor symbols. Unknown old declarations prove neither automatic ownership nor obsolete parameter removal. Every dependency batch requires a valid complete final state.

Required Implementation fields are compared through complete old and final Interface selection closures, independently of Resource provider completeness or binding validity. Dormant choices retain configuration ownership but become newly reachable only when activated. An incomplete old Interface closure proves no newly reachable fields; final validation remains mandatory. A previous-constructor alternative is offered only after its complete state validates.

Single-Resource provider previews enumerate only final-state-validated binding assignments, even when old selected Config or obsolete bindings are invalid. Invalid previous states are never offered as provider-retention alternatives. Typed lower layers, unrelated final obligations, cycle rejection, and the 64-probe bound remain enforced.
