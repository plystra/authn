# Plystra AuthN

`github.com/plystra/authn` is an independent Plystra Project created through the public CLI.

Status: **Development; not production ready**. The Project builds and provides bounded credential-input validation, the session verification contract and its trusted-state helper, and bounded Argon2id password hashing. A persistent authentication service and full product acceptance remain incomplete.

AuthN owns accounts, credentials, authentication protocols, sessions and verified caller state. Persistence must use the independent `github.com/plystra/data` module and its selected Resource; AuthN never imports AuthZ or opens a second database pool.

The complete product target is specified in the separate `authn-docs` repository. Kernel and CLI remain generic. Ordinary Go contracts and explicit constructor injection connect the products.

Keep current-Project requirements, selections, Resource bindings and HTTP exposure explicit in `plystra.yaml`. The CLI owns `generated/` and `.agents/skills/plystra/`; use its public generation workflow to update them.

`credentialinput.FromContext` validates the complete Core `plystra.http-credential-metadata/v1` schema, including duplicate and unknown fields, canonical Interface identity, sorted unique cookies and all byte/count bounds. Missing input is valid; malformed input fails without reflecting credentials. Candidate formatting, JSON and structured logs redact contents, and accessors stop returning input after context completion. The selected verifier must still reject simultaneous usable Bearer and session-cookie credentials and verify authoritative session state. Parsing alone creates no trusted state.

## Session verification and trusted state

`interfaces/authn/session/verify/v1` owns the one-method `authn.session.verify/v1` contract. The request is empty; an injected implementation consumes bounded unverified credential metadata from its ordinary invocation context. Its response carries issuer, `user` or `service` subject kind, subject ID, opaque session ID, audience, positive subject/session revisions and expiry. These are facts, not authority. An AuthZ human, agent or application member is resolved separately from authenticated facts.

`verifiedstate.New(session, verifiedstate.Options{Issuer: "shop", Audience: "shop-api"})` constructs an ordinary helper. Call `ctx, subject, err := verifier.Verify(ctx)` explicitly and continue with the returned context only on success. The helper rejects malformed identifiers (1-256 UTF-8 bytes, no control characters), mismatched issuer/audience, invalid kinds or revisions, expired facts and failed or cancelled calls. Every failure returns the input context unchanged and a zero subject. Direct cause-free declared Kernel semantic errors and safe runtime classifications are retained; arbitrary provider messages, wrappers, private causes and panic values are discarded. Kernel's bounded, panic-safe `CompletionOf` traversal preserves uncertainty with a new cause-redacted `NewResultUnknown` marker, including when the context was cancelled after the call. An incomplete error traversal remains uncertain.

Only this helper creates opaque process-local attestations. `FromContext`, `Attestation.Subject` and `Attestation.Same` reject invalid, expired, cancelled or locally invalidated state. A serialized Subject, response, attestation or arbitrary context value cannot create trust. Formatting and structured logging of helper values and response facts redact identities, bindings and session IDs. Explicitly extracting fields or encoding protocol response data still requires appropriate handling by the caller.

`MaxReuse` defaults to zero: every later `Verify` calls the injected Interface again, while newly created state remains consumable. An explicit value up to five minutes allows reuse only within the originating context lineage and verifier identity, before the reuse limit, expiry, cancellation or invalidation. An independently constructed verifier does not reuse another verifier's state. Cancellation of the original verification context remains binding even through `context.WithoutCancel`.

After a persisted mutation commits, its implementation calls `InvalidateSession(issuer, sessionID, currentRevision)` or `InvalidateSubject(subject, currentRevision)`. A newer positive revision raises the local high-water mark and advances its generation; existing attestations become invalid even when their captured revision was higher. Equal/older events are no-ops. Fresh results at or above the mark can create new state. Invalid keys or revision zero change nothing. Invalidation is synchronous, concurrency-safe and performs no I/O. The tables last for the process lifetime; distributed propagation, persistence and transaction integration are not supplied by this helper. In-flight state is a bounded snapshot, not a guarantee against remote mutation or a rollback of completed effects.

No session verifier implementation, database stub, public HTTP exposure or AuthZ dependency is included. The public CLI records the unselected contract in generated metadata and wire history; generation is not session-service acceptance. The helper is verified through named external-package normal and race tests covering malformed facts, cancellation, expiry, reuse, invalidation ordering/concurrency, opaque state and redacted failures.

## Bounded password hashing

`passwordhash.New(passwordhash.Options{})` returns a concurrency-safe helper with Argon2id v19 from `golang.org/x/crypto` v0.57.0. `Hash(ctx, []byte)` uses `crypto/rand` for a fresh salt and returns a PHC record. `Verify(ctx, []byte, record)` uses the stored parameters and a constant-time key comparison, returning `Result{Match, NeedsUpgrade}`. A mismatch returns both flags false with no error; malformed records and resource failures return a zero result and a safe classified error. Passwords are 1-1024 bytes, preserved exactly. Account complexity, normalization, breached-password checks, persistence and login policy remain the calling service's responsibility. Keep the caller-owned password slice stable until the call returns.

The default target is 65536 KiB memory, three iterations, four lanes, a 16-byte salt and a 32-byte key. An entirely zero `Parameters` selects that target; a partial profile is rejected. Explicit profiles and stored records require 1-6 iterations, 1-8 lanes, memory from eight KiB per lane through 262144 KiB, and salt/key lengths of 16-64 bytes. The low parser floor supports verifying weaker historical records; new-account policy must select its intended target explicitly or retain the stronger default. Only canonical `$argon2id$v=19$m=...,t=...,p=...$salt$key` records up to 256 bytes are accepted. The parser rejects signs, overflow, leading zeros, missing/duplicate/unknown/reordered parameters, noncanonical unpadded standard base64, whitespace, unsupported versions and excessive decoded lengths before expensive allocation or derivation.

Each instance has explicit `MaxConcurrent`, `MaxMemoryKiB` and `MaxLanes` admission limits. Individual zero limits select defaults of two jobs, 131072 KiB and eight lanes; hard instance ceilings are 64 jobs, 1048576 KiB and 64 lanes. Construction rejects a target that cannot fit its instance. Verification charges the stored profile, not the target profile. Permanently excessive work returns `ErrResourceLimit`; temporary saturation returns `ErrBusy` immediately without queueing. Copies share admission; independently constructed instances have separate budgets, so deployment composition must bound the number of instances. These limits bound active Argon2 work, not process RSS or GC retention.

Context cancellation and deadlines are checked before admission and after derivation. Argon2 itself is synchronous and cannot be interrupted; a cancelled caller receives no hash or match result, and capacity remains reserved until computation ends. The helper starts no background cancellation worker. Its own derived-key buffers are cleared after use; it does not promise erasure of caller memory or Argon2's internal allocations.

`NeedsUpgrade` is available only after a match. It is conservative: the target must not reduce the stored memory, effective memory after lane rounding, iterations, salt length or key length, and must increase at least one strength dimension. A lane-count change alone is not an upgrade, and mixed stronger/weaker profiles do not trigger a replacement that could downgrade the stored hash. The login implementation must separately perform a revision-bound atomic replacement and handle concurrent password changes; this package writes nothing.

Named external-package normal/race tests cover the real default derivation, strict malformed-input bounds, stored-cost admission, cancellation, concurrency, exact password bytes and upgrade behavior. The parser fuzz target uses a small explicit resource budget; it does not exercise production-cost load or persistence. All persistence and complete product acceptance remain incomplete.

## Opaque credential cryptography

`opaquecredential` is a standard-library-only primitive for the high-entropy secret components required by AuthN domain requirements N6-N8, protocol P5 and security S1. `NewKey(KeyRef{ID, Version}, material)` copies a provisioned 32-64-byte HMAC key. `New(active, previous...)` constructs an immutable ring of at most 32 unique key references, with exactly one active write key. Missing/invalid keys or duplicate references fail construction; there is no unkeyed SHA-256 fallback, key scan, implicit key generation or external lookup. Key provisioning must supply appropriate randomness and separate keys from data-encryption/signing purposes. Caller buffers can be cleared after construction; the package does not promise erasure of every in-process key copy.

`Ring.Generate(Binding{Kind, Purpose, ID})` returns a fresh 256-bit `crypto/rand` secret and an HMAC-SHA-256 digest. Kinds are closed: session, refresh, application key, Agent key, one-time capability and device code. Purpose is an explicit server-owned identifier (1-128 UTF-8 bytes); ID is the exact credential record ID (1-256 bytes). Key IDs are 1-64 bytes and key versions are positive uint32 values. All identifiers reject invalid UTF-8 and control characters and are compared exactly without trimming. A kind/purpose/ID is a cryptographic namespace, not authority supplied by a caller.

`Secret.Reveal()` explicitly delivers the unprefixed 43-character canonical unpadded base64url secret component; `Parse` validates that exact component with strict pad-bit and length checks. Method-specific adapters still own the complete domain wire formats, including `ply_rt_`, `ply_sk_<id>.<secret>` and the `ply_ag_` profile. This primitive defines no replacement token wire format, human OTP/backup-code format, JWT or signing protocol. A parsed value remains unverified input.

Persist the digest's explicit `Version()`, `Key()` (key ID/version) and defensive-copy `Bytes()` outputs alongside the owning record's binding and state; reconstruct with `Restore`. Format v1 MACs the fixed UTF-8 domain `plystra.authn.opaque-credential/hmac-sha256/v1`, big-endian uint32 format version, length-prefixed key ID, uint32 key version, then length-prefixed kind, purpose, credential ID and raw secret bytes. Every length is big-endian uint32 and counts bytes. Unsupported format versions or malformed stored digests fail closed. Key, ring, binding, reference, secret, digest and result types redact fmt/text/JSON/slog output; generic text/JSON decoding is rejected. Explicit accessors return sensitive material for deliberate delivery/storage and must not be logged.

`Ring.Verify(binding, candidate, stored)` uses only the exact stored key reference and a constant-time digest comparison. `Result.Match` is a cryptographic match, not an authenticated caller. On a match under a retained old key, `NeedsRehash` and `Replacement` provide a digest under the active key; mismatches produce neither. Deploy new verification keys before activating a new write key, and replace persisted digests only during controlled verification with the service's current-state and revision checks. Removing a key makes its remaining records unverifiable; a lost secret cannot be reconstructed or rehashed from its digest.

Expiry, one-time consumption, refresh replay/family revocation, cross-plane credential parsing, service-subject authority, audit and atomic delivery after an acknowledged commit remain service/Data integration work. Repeated verification can continue to match because this package stores and consumes nothing, creates no trusted-state attestation and imports neither Data nor AuthZ. The full authentication product remains incomplete. Named public normal/race tests cover these primitive guarantees and limits; a bounded candidate/digest fuzz target exercises malformed input.
